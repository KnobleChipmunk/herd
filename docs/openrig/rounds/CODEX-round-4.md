## Corrections and order

The original “daemon-enforced rails” description overstated semantic enforcement: OpenRig's runtime records transitions while agents judge completion ([architecture](https://openrig.dev/docs/architecture)). Our earlier treatment of queue value chiefly as lost-prompt protection was too narrow: attributable work is independently useful. Neither correction requires adopting OpenRig's whole architecture.

The report also overstates snapshot certainty: stopping attempts a snapshot, but failure does not prevent teardown ([continuity docs](https://openrig.dev/docs/continuity)). The demo uses fictional data ([TUI docs](https://openrig.dev/docs/tui)); it illustrates behavior rather than proving long-running reliability. The pages `/docs/what-is-a-rig`, `/tour/scope`, and `/tour/feedback` were inaccessible; details unique to those pages remain **UNVERIFIED**. All untested local compatibility claims remain **UNVERIFIED**.

Proposed order: `0 → 2 + 1a → P → 5 + 6a + ownership part of X → 3 + 4 + C + remaining X → W`. P selects implementation approach; it does not remove any of the seven target capabilities. Rows not discussed retain their settled scope and ratings.
